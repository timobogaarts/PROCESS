# Unit registry — Phase 0, stellarator scope

Scope rule (derived by tracing `Stellarator.run()`'s actual call surface, not assumed):
**all of `process/models/stellarator/**` in full, plus only the specifically-called
methods (and their direct callees) on `Stellarator`'s injected sub-models** — not those
shared files' entirety. Injected sub-models per `Models.__init__` (`process/main.py`):
`availability`, `buildings`, `vacuum`, `costs`, `power`, `plasma_profile`, `hcpb`
(CCFE-HCPB), `current_drive`, `physics`, `neoclassics`, `plasma_beta`,
`plasma_bootstrap`. Of these, `current_drive`/`plasma_beta`/`plasma_bootstrap` are never
called directly by `stellarator.py` (grep for `self.current_drive.`/`self.plasma_beta.`/
`self.plasma_bootstrap.` in `process/models/stellarator/*.py` returns nothing) — they're
reached only indirectly, through `self.physics.*` methods that were themselves
constructed with those sub-models in `main.py`. Not in scope directly; may surface as
transitive callees of the `physics.py` methods below and get their own row then.

reviewed) / `reviewed` (you've checked flagged items) / `final`.

**Standing practices**, all still in force:

- **A chunk confirmed tier-1 *and* self-contained is ported as part of finishing its
  audit**, not queued: function + node + harness test class. A self-contained tier-2 chunk
  gets the same treatment via `ImplicitFunction`/`FixedPointFunction`. Entangled, tier-3, or
  tier-2-calling-an-unported-unit chunks stay audit-only until the dependency resolves.
- **Porting a unit's tier-1 functions is not the same as its audit reaching `reviewed`.** A
  unit with an open tier-2 half stays `draft`; a unit that is *entirely* tier-1 and fully
  ported moves to `reviewed`, because a passing suite is stronger evidence than an
  unreviewed audit claim.
- **Every ported node is registered in `total_process.py`**, and
  `python -m functional_process.render_xdsm` redraws the graph to
  `functional_process/xdsm.html`. Both are kept current as units land.
- **There is no longer a single graph.** A node whose existence depends on a
  topology-changing switch is registered as an `Alternative` under that switch in
  `TOPOLOGY_SWITCHES`, not in `COMMON`; `graph_for(configuration)` assembles the arms one
  configuration selects. A ported arm reachable from no configuration is dead code and
  `test_configuration.py` fails on it — the state `LowhybHeating` and
  `AFwTotalNoPowerflow` were in before this existed.
- **`Alternative` has three states**, and the distinction matters: `declarations` (ported),
  `unported` (refuses to assemble — a caller asking for it has a model this graph has never
  seen), and `unproduced` (assembles as empty, so the arm's outputs simply have no
  producer). `unproduced` is a *weaker* guarantee and is only sound when nothing else
  produces those outputs — see `next_steps.md` §9.

**PROCESS defects reproduced faithfully rather than fixed** — each is recorded in its
unit's own `.md`, and the standing rule is that the port reproduces PROCESS's behaviour and
the record names the defect: `blanket_neutronics()`'s two zero-argument `hcpb` calls (#13);
`jcrit_from_material`'s 3-positional-arg call into a 2-argument `jcrit_rebco` (#22);
`calculate_confinement_time`'s scrambled `KAYE_GOLDSTON` positional call and its
`USER_INPUT`/`PAZ_SOLDAN_NT` dead branches (#10); `calculate_bldgs_sizes`'s self-divided
`hcomp_req_supply` (#15); `avail_2`/`avail_st`'s sign error in the total-availability cross
term and their unconditional divide by `f_t_plant_available` (#17); and `acc223`'s two
defects — `c2233` computed only when `ifueltyp == 1`, and `fkind` applied only on that same
branch — plus the dead field `.costs.c2234` (#18).
